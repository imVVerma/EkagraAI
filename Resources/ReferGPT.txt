# 2. JSON usage

Use the JSON like this:

### Teaching

Use:

```text
doctrinal_anchors
transition.concept_to_master
selected case content
selected pedagogy
```

to create the teaching turn.

For Phase 1, the teaching service can return deterministic mock text.

### Checkpoint

After the teaching turn:

1. Select the current case.
2. Select one of its `question_variants`.
3. Show the case/question to the learner.
4. Wait for the learner response.

Never show a checkpoint before its teaching turn.

### Scoring

Use:

```text
transition.target_signature
case.level_examples
case.edge_case_notes
global_response_handling_rules
```

to determine the expected scoring behavior.

For Phase 1, use a simple deterministic mock scorer.

Keep the scorer behind an interface so it can later be replaced with an LLM scorer.

# 3. State machine

Implement:

```text
START
  ↓
SELECT TRANSITION
  ↓
SELECT PEDAGOGY
  ↓
TEACH
  ↓
CHECKPOINT
  ↓
LEARNER RESPONSE
  ↓
SCORE
  ↓
PASS ─────────────→ NEXT TRANSITION
  │
  FAIL
  ↓
SELECT ANOTHER UNUSED PEDAGOGY
  ↓
TEACH
  ↓
CHECKPOINT
  ↓
LEARNER RESPONSE
  ↓
SCORE
```

There are exactly three pedagogies:

* Worked Example
* Guided Questioning
* Contrasting Cases

At the start of every transition, all three are available.

Select one randomly.

After failure, remove the pedagogy already used in that transition.

Never repeat a pedagogy within the same transition.

When the learner advances to the next transition, reset the pedagogy pool.

---

# 4. Teaching service

Create a small abstraction such as:

```python
TutorService.generate_teaching_turn(...)
```

For now, implement a mock version.

It should demonstrate the three pedagogy styles:

### Worked Example

Return a solved example followed by explanation.

### Guided Questioning

Return an incremental sequence of guiding questions.

### Contrasting Cases

Return two closely related scenarios and highlight the relevant difference.

The checkpoint question must NOT be included in the teaching output.

Later, this service will be replaced with an OpenRouter implementation.

# 5. Scoring service

Create:

```python
ScoringService.score_response(...)
```

For Phase 1, use deterministic/mock scoring.

Return at least:

```json
{
  "assigned_solo_level": "...",
  "target_signature_met": true
}
```

The rest of the application should not know whether scoring is mock-based or LLM-based.

Later, OpenRouter will replace this implementation.

# 6. Demonstration path

The primary demonstration must work with:

```text
C1
Case 1A
Border Aggression
```

The flow should visibly demonstrate:

```text
C1
↓
Pedagogy selected
↓
Teaching
↓
Border Aggression checkpoint
↓
Learner response
↓
SOLO classification
↓
PASS / FAIL
```

Also demonstrate the failure path:

```text
Pedagogy A
↓
FAIL
↓
Pedagogy B
↓
NEW TEACHING TURN
↓
NEW CHECKPOINT
```

A retry must never be a bare re-ask of the previous checkpoint.

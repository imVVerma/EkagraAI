# EkagraAI: Fix Pre-Pilot Blockers

The Pre-Pilot Verification has been completed.

The system is NOT ready for live evaluation yet.

The report identified four blockers:

1. Silent deterministic fallback in live mode.
2. `tools/l1_pilot.py` does not actually invoke LLM1.
3. Structured-output validation can silently skip if `jsonschema` is unavailable.
4. Provider key ambiguity between `EKAGRA_API_KEY` and `EKAGRA_GROQ_API_KEY`.

Fix ONLY these blockers.

Do not start the live pilot yet.

Do not ask for or use an API key.

Do not build LLM2.

Do not select a final model.

---

## 1. Remove Silent Deterministic Fallback in Live Mode

Current problem:

`backend/server.py` has catch-all exception handlers in:

* `/api/teaching-turn`
* `/api/checkpoint`
* `/api/respond`

that fall back to deterministic behavior.

This is unacceptable during controlled LLM experiments because a failed LLM1 call can be recorded as if LLM1 succeeded.

Implement explicit behavior:

### Deterministic mode

Existing deterministic behavior may remain.

### Live mode

If LLM1 fails for any reason:

* provider error
* timeout
* authentication error
* network error
* rate limit
* structured-output error
* budget error
* model error

then:

1. Do NOT generate deterministic replacement content.
2. Record the failure.
3. Preserve the typed error.
4. Associate it with experiment_id and run_id.
5. Return an explicit failure response.
6. Mark the corresponding pilot case as failed.
7. Allow the pilot runner to continue to the next independent case where safe.

A live LLM experiment must never silently substitute deterministic output.

Add:

```text
EKAGRA_ALLOW_DETERMINISTIC_FALLBACK
```

Default:

```text
false
```

When `EKAGRA_MODE=live`, deterministic fallback must remain disabled unless explicitly and intentionally enabled.

Prefer:

```text
live + fallback=false
```

for all controlled experiments.

Do not catch `Exception` and convert it into successful tutor content.

---

## 2. Make Structured Output Validation Fail Closed

Current problem:

`jsonschema` is treated as an optional import, and validation can silently pass if it is unavailable.

Fix this.

The system must fail closed.

If structured-output validation is required and `jsonschema` is unavailable:

```text
StructuredOutputError
```

or an appropriate configuration/dependency error must be raised.

Do NOT silently accept unvalidated structured output.

Add/update dependency declarations so that `jsonschema` is an explicit required dependency for the LLM foundation.

Run the relevant tests in an environment where the dependency is installed.

Add a test confirming that malformed structured output is rejected.

---

## 3. Fix Provider Key Selection

Current configuration is ambiguous:

```text
EKAGRA_API_KEY
OPENROUTER_API_KEY
EKAGRA_GROQ_API_KEY
```

and the current logic effectively resolves:

```text
EKAGRA_API_KEY
or OPENROUTER_API_KEY
or EKAGRA_GROQ_API_KEY
```

This means a generic API key can accidentally be used for the wrong provider.

Implement explicit provider-aware credential resolution.

Desired behavior:

### OpenRouter

Prefer:

```text
EKAGRA_API_KEY
```

or retain the existing OpenRouter-specific backward-compatible variable if necessary.

### Groq

Prefer:

```text
EKAGRA_GROQ_API_KEY
```

Do NOT allow an OpenRouter key to silently become a Groq key.

If a provider-specific key is missing, fail clearly with `AuthenticationError` or configuration error.

Do not print the key.

Do not log the key.

Do not remove backward compatibility unless necessary.

Document the exact environment variables in `.env.example`.

## 4. Rewrite `tools/l1_pilot.py`

This is the most important fix.

The current pilot is not actually a live LLM1 pilot.

It must invoke the real LLM1 service.

The intended path is:

```text
Pilot case
    ↓
Tutor state
    ↓
ContextSelector
    ↓
LLM1Tutor
    ↓
Provider adapter
    ↓
real LLM response
    ↓
structured-output validation
    ↓
deterministic scorer
    ↓
state machine
    ↓
decision trace
    ↓
usage/cost log
```

Do not create a parallel fake LLM1 implementation.

Reuse:

```text
backend/llm1_tutor.py
backend/context_selector.py
backend/state_machine.py
backend/scoring_service.py
backend/llm/provider_interface.py
backend/llm/decision_trace.py
backend/llm/usage_store.py
backend/llm/budget.py
```

where appropriate.
